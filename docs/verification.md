# Фактические проверки стенда

## Проверка балансировки при развёртывании

В deploy после verify.yml добавлен verify_balance.yml: round-robin и hash
проверяются существующим HTTP-скриптом без параметра --fault. Возврат
к round-robin выполняется в always. Новый Ansible-сценарий ещё не проверен
на облачном стенде; прежние HTTP-проверки ниже не подтверждают его выполнение.

## Обновление: единый terraform apply

Добавлен `terraform_data.configuration`, запускающий настройку и verify.yml
после создания ВМ. Проверены Terraform fmt/validate и plan на пустом state:
13 добавлений, без изменений и удалений (12 облачных ресурсов и этап настройки).
Локальный тест подтвердил передачу кодов 0 и 7 от дочернего процесса и сохранение
stdout/stderr в журнал. Python-синтаксис проверен.

При ручной проверке в Windows единый apply успешно завершился после исправления
запуска Python: заменён только `terraform_data.configuration` (1 added,
0 changed, 1 destroyed), адрес стенда — 158.160.49.206. В предоставленном выводе
последующих тестов подтверждены оба алгоритма и четыре сценария отказов:
round-robin 15/15, hash 16/24, в каждом отказе 12/12 запросов обслужены web2,
web1 восстановился. Итоговый режим — round-robin.

Идемпотентность этого развёртывания подтверждена отдельным повторным site.yml:
на db, lb, web1 и web2 `changed=0`, `failed=0`, `unreachable=0`.
[Журнал ручной проверки](logs/07-idempotence-redeploy.txt) сохранён из вывода
PowerShell. Проверка полного цикла destroy → создание с нуля → destroy
выполняется отдельно; её завершение пока не подтверждено.

После ошибки экранирования пути Python в Windows provisioner переведён на
прямой запуск Python через `interpreter`, без cmd.exe. Отдельный локальный
Terraform apply с этим способом запуска успешно выполнен, в том числе из
каталога с пробелом. Облачные ресурсы этот тест не создавал и не изменял.

Ниже приведены результаты первого развёртывания 22 сентября 2026 года.
Они относятся к прежнему раздельному запуску Terraform и Ansible и не описывают
текущее состояние ресурсов во время проверки полного цикла.

## Окружение и границы проверки

API Galaxy был недоступен с контроллера. Коллекции установлены штатным пакетом
Ansible из PyPI в venv; этот способ закреплён в `ansible/requirements.txt`.
Локальный Windows Python, отмеченный Symantec, повторно не запускался:
настройка продолжена через OpenSSH/SCP, Ansible работал в Linux-venv на lb.
Причина обнаружения Symantec не установлена и ложным оно не объявлено.

Terraform fmt/validate, синтаксис PowerShell, Python и Bash, Ansible syntax-check
и pip check пройдены. Полный цикл с отдельного Linux-рабочего места не запускался;
инструкция Linux предоставлена для воспроизведения. Итоговый Terraform plan
завершился без изменений.

Проверялись отказы служб одного веб-узла и запросы GET. Отказ ВМ целиком,
балансировщика, MySQL, NFS, зоны и нагрузочная устойчивость не проверялись.
Общая БД и NFS не кластеризованы; HTTPS и резервное копирование не настроены.
